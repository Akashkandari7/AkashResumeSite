Case study · 2026 – present · contract, sole developer

Dragon Pit — asset platform & Blender add-on

For The Future Animations, a 3D animation studio. Internal tool, not public.

  • ~100 daily users
  • 600+ assets
  • 560 GB on R2

The problem

The studio had hundreds of bought and in-house 3D models spread across drives and store accounts. Animators couldn't easily see what existed, and every new script meant someone reading it line by line to work out which characters, sets and props were needed and whether the studio already owned them.

What I built

  • The library site — Next.js (App Router) and TypeScript on Vercel, Prisma with PostgreSQL on Supabase, files on Cloudflare R2.
  • AI script breakdown — a two-stage Gemini pipeline: read the script and list what it needs, then cast each item against the catalog. Structured JSON output, per-script caching, model fallbacks, quota handling, and deterministic rules on top of the model's answers.
  • The Blender add-on (Python, bpy) — browse the catalog, one-click import, script matching, animation retargeting onto Character Creator, Rigify and Mixamo rigs, and self-update with a kill switch for old versions.
  • Access & admin — role-based access with daily download limits, usage graphs, access requests, per-user download history, and a shopping list of things scripts asked for that the library didn't have.

Interesting bits

  • The offline matcher exists twice — TypeScript on the site, Python in the add-on — with an automated parity check so Blender and the browser can never disagree about the same script.
  • Read the indexes of 600 zip files over HTTP range requests instead of downloading terabytes, to measure exactly what each asset contains.
  • Headless Blender jobs pack textures into single .blend files and render previews; audits catch a missing texture before an animator does.
  • Closed a Supabase security alert by turning on row-level security on every table, verified end to end with no downtime.
