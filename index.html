Case study · Internal studio tool

Dragon Pit — Asset Platform & Blender Add-on

Contract work as the sole developer for The Future Animations, a 3D animation studio. The studio had hundreds of bought and in-house models spread across drives and store accounts, and every new script meant someone reading it line by line to work out which characters, sets and props it needed. Dragon Pit puts the whole library in one place and reads the script for you.

~100animators, daily
600+assets
560 GBon Cloudflare R2
2clients: web + Blender

What I built

  • The library site — Next.js (App Router) and TypeScript on Vercel, Prisma with PostgreSQL on Supabase, files on Cloudflare R2.
  • AI script breakdown — a two-stage Gemini pipeline: read the script and list what it needs, then cast each item against the catalog. Structured JSON, per-script caching, model fallbacks and quota handling, with deterministic rules on top.
  • Blender add-on (Python, bpy) — browse, one-click import, script matching, animation retargeting onto Character Creator, Rigify and Mixamo rigs, and self-update with a kill switch for old versions.
  • Access & admin — roles with daily download limits, usage graphs, access requests, per-user download history, and a shopping list of what scripts asked for but the library didn't have.

Interesting bits

  • The offline matcher exists twice — TypeScript on the site, Python in the add-on — with an automated parity check so Blender and the browser never disagree about the same script.
  • Read the indexes of 600 zip files over HTTP range requests instead of downloading terabytes, to measure exactly what each asset contains.
  • Headless Blender jobs pack textures into single .blend files and render previews; audits catch a missing texture before an animator does.
  • Closed a Supabase security alert by turning on row-level security on every table, verified end to end with no downtime.
